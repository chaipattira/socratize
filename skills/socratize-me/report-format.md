# Reviewer Report Format

Every reviewer agent returns a report in exactly this shape. Report findings; do not vote
pass/fail.

## Strengths

[What's well done? Be specific — cite the section or line, not "good structure".]

## Issues

### Critical (Must Fix)

### Important (Should Fix)

### Minor (Nice to Have)

For each issue, use:

- **`file:line`** — location
- **What's wrong** — the defect, concretely
- **Why it matters** — impact on the reader/reproducibility/correctness
- **How to fix** — concrete change (omit only if truly obvious)

If a severity bucket is empty, write "None." Stay strictly within your assigned lens.
